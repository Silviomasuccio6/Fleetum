# Security reporting

Report suspected Fleetum vulnerabilities through
[GitHub's private vulnerability reporting form](https://github.com/Silviomasuccio6/Fleetum/security/advisories/new).
Use a private report for security-sensitive information; ordinary usability and
feature requests can use the normal issue tracker.

Include the affected component and revision or version when known, the expected
and observed behavior, the potential impact, and minimal reproduction steps using
synthetic data. Redact passwords, tokens, personal data and customer documents.
Keep exploitation details and attachments within the private report rather than
public issues, pull requests or discussions.

Maintainers will assess the report and coordinate any further disclosure through
the private conversation. A green automated check is not a security certification.

Repository security automation and its verification limits are described in
[the security controls guide](docs/security/github-controls.md).
